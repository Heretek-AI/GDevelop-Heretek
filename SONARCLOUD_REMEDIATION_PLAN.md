# SonarCloud Remediation Plan

## Context

SonarCloud reports **10,289 open issues** on `Heretek-AI/GDevelop-Heretek` (capped at 10,000 per API call). The previous PR (#5) closed 0 of these — it was scoped to Dependabot + secret-scanning + CodeQL, not SonarCloud. This plan picks up where that left off, scoped to what's actually fixable vs. suppressible.

**Goal:** reduce the open-issue count to a steady-state we can keep under control, without dragging the PR review process through 2,000 style-only diffs.

**User decision captured (2026-08-20):** scope the remediation around the issue profile below; suppress / ignore the rest. Do NOT try to drive the count to zero.

## Remediation plan

### Phase 1 — Configuration (no code logic)

**1a.** Exclude vendored / generated paths from SonarCloud's source set so they stop counting against us.
- Add `sonar.exclusions` (or extend `.sonarcloud.properties` if it exists) to skip:
  ```
  Extensions/Spine/spine-pixi-v7/**
  newIDE/app/src/EditorFunctions/index.js   # auto-generated
  newIDE/app/src/EditorFunctions/SimplifiedProject/**   # codemod output
  GDJS/Runtime/gameplay-tests/**   # if low-value
  ```
- Estimated impact: **~800-1,000 issues** drop from "open" without code changes.

**1b.** Enable `sonar.issue.ignore.block` / `won't fix` for patterns we accept (intentional):
- `javascript:S3504` (var→const) — accept as `won't fix` for vendor code; fix in our active source via autofixer.
- `javascript:S3358` (nested ternaries) — accept for legacy code; refactor in active code.
- `javascript:S7773` (mixed tabs/spaces) — fix in tracked files via `prettier`.

**1c.** Drop `sonar-scanner` coverage of vendored runtime files (`pixi.js`, `three.js`, `monaco-editor`, `nanomarkdown.js`, `rbush.js`, `howler.min.js`).

### Phase 2 — Real fixes (small batch, high signal)

In priority order:

1. **2 BLOCKER** vulnerabilities (`S2076` in `electron-app/app/main.js`, `S2083` in `fix-codemod-syntax.py`).
2. **5 CRITICAL** vulnerabilities (`S8707`, `S1523` for eval, `S2245` crypto RNG, etc.).
3. **CI workflow hygiene**: `--ignore-scripts` (S6505), pinned `uses:` (S8543), minimal write permissions (S8233).
4. **PATH injection** (S4036) in build scripts.
5. **Test assertion quality** (S4138 / S6836) — replace `assert.ok(...)` with specific matchers in test files we actually maintain.

**Estimated impact:** closes ~30-50 issues of the highest severity and pulls the security rating up to A.

### Phase 3 — Suppress the rest in bulk

After Phase 1 + 2, the remaining ~9,500 issues are overwhelmingly:
- Code-style nits in long-lived files (`var` vs `const` etc.)
- Cognitive-complexity warnings in AI/Editor/Generator code (S3776)
- Nested ternaries in legacy code
- Missing `assert` argument in test cases
- Identical sub-expressions on operator sides

For these, add a `.sonarcloud.properties` ignore block (or commit per-issue `won't fix` resolutions via the UI):

```
sonar.issue.ignore.multicriteria=e1,e2,e3,e4,e5,e6,e7
sonar.issue.ignore.multicriteria.e1.ruleKey=javascript:S3504
sonar.issue.ignore.multicriteria.e1.resourceKey=**/*.spec.js
sonar.issue.ignore.multicriteria.e2.ruleKey=javascript:S3776
sonar.issue.ignore.multicriteria.e2.resourceKey=newIDE/app/src/EditorFunctions/**
sonar.issue.ignore.multicriteria.e3.ruleKey=javascript:S3776
sonar.issue.ignore.multicriteria.e3.resourceKey=newIDE/app/src/AiGeneration/**
sonar.issue.ignore.multicriteria.e4.ruleKey=javascript:S3358
sonar.issue.ignore.multicriteria.e4.resourceKey=Extensions/Spine/**
sonar.issue.ignore.multicriteria.e5.ruleKey=javascript:S4138
sonar.issue.ignore.multicriteria.e5.resourceKey=newIDE/app/src/EditorFunctions/**
sonar.issue.ignore.multicriteria.e6.ruleKey=javascript:S6836
sonar.issue.ignore.multicriteria.e6.resourceKey=**/*.spec.js
```

**Estimated impact:** drops another ~3,000-5,000 issues by suppressing patterns we accept as intentional. Brings the open count into the **~2,000-4,000 range** (manageable steady state).

## Risks & open questions

1. **SonarCloud API token for write operations.** Phase 1c and Phase 3 require pushing a `sonar-project.properties` (or `.sonarcloud.properties`) to the repo, AND setting `sonar.issue.ignore.multicriteria` via the Web API. The multicriteria block is committed to the repo, but SonarCloud's "ignore" rules live server-side and need either: (a) a project-level SONAR_TOKEN repo secret, or (b) manual UI dismissal. We don't have the token; for Phase 3 I'll generate the multicriteria block in `SONARCLOUD_REMEDIATION_PLAN.md` and the operator can paste it into the SonarCloud UI under Project Settings → Issues → Exclusions.
2. **Excluding `B_spine-pixi-v7.js`** is the right move (it's vendored code we don't maintain), but the user should know that this is a "suppress by exclusion" approach, not a fix. If upstream `4ian/GDevelop` ever updates the vendored copy, the exclusions still apply — that's fine.
3. **`EditorFunctions/index.js`** is auto-generated by the codemod script in `newIDE/app/scripts/`. Excluding it prevents new issues from being filed every time the codemod runs. Same approach as Spine.
4. **The "won't fix" suppressions** may bother some contributors. Document each in this file so reviewers can challenge them. If the user wants a stricter posture (e.g., "fix all CRITICAL"), the plan expands significantly — Phase 2 alone becomes a multi-week effort.
